# Deneva 执行与真实叶节点锁移植

## 约束与目标

逐项参照实际 Deneva，而非声称复制整个分布式数据库。保留四个锁接口、公共事务驱动与六版公共页布局；索引只做结构 latch 和返回稳定对象身份，事务锁对象由锁模块独立保存。完整正式矩阵禁止自动启动。源码问题（缺失远端写回、错误位段回滚、未保护的读和提前释放）修正后实现。

## 顺序与不变式

1. 数据路径：现有记录的普通更新不改结构、不改 live_records，持结构共享 latch 后按记录偏移排序取得短期记录 latch，整批写回 value 后释放短 latch；只有缺失键/删除/复活才进入结构排他路径。所有读值同样取得记录共享 latch，不混 CPU 原子与 NIC 原子。保留多写集严格事务锁直到整个写批次结束。未知数据写失败 poison 并保留物理事务锁。
2. 真实叶节点：公共索引返回实际叶页身份和路由范围（含边界空隙）。本地页添加单调 ID，远端使用页偏移归一化 ID。不使用 bucket 算术代替 leaf。事务层按 root→leaf→record 汇总最终模式，无持锁升级。范围读对覆盖的叶页取 S；点读/更新分别取叶 IS/IX 和记录 S/X；混合 scan/write 叶取 X。
3. 锁对象：新增本地/RDMA 同语义精确对象管理器。对应 Deneva 行首 _tid_word/holder 元数据，但锁字位于独立注册区，通过稳定 leaf/record ID 索引，锁模块不接触页。每对象短期 CAS 保护持有者链表，无 16 shard gate 或全片锁槽扫描；全局分配仅会话建链时发生，持有者节点每会话固定预算预分配/回收，热路径不全局分配。保留事务 ID 持有者以支持三种年龄策略，不能只复制不含 owner 的 FAA 计数。
4. 分裂/删除：先采用显式 topology 对象 S/X 事务锁。无结构变化的事务持 S，含 Insert/Delete 的事务持 X，使叶身份从规划到 commit 稳定；真实结构操作仍由索引 latch 保护。该保守屏障使结构事务串行，但不串行普通更新；如实记录，不声称具有 Deneva 或 Sherman 完整结构扩展性。后续有经测试的 split 锁转移方案后方可去掉，禁止在实现不完整时默默丢失幻读保护。
5. 同一协程/并发预热/阶段排空继续共用。叶模式独立 CSV/配置标识，不把 bucket 旧数据混入；接口变更独立提交，每里程碑硬件 CTest。

## 验证

并发独立记录更新必须在一个写者停在真实写回前时允许另一个写者完成（不能只测吞吐）；相同记录读写互斥；整批应用前容量预检；真实 WC 失败拒绝有效测量。叶覆盖涵盖空树、开闭边界、最大 key、split 前后真实页 ID；叶 S 阻止同叶记录更新、允许其他叶更新；两机三策略精确增量和 phantom/插入/split 压力。正常及异常预热边界均验证。只跑定向负载和稳定性，不启动正式矩阵。

## 本轮实现与定向检查

真实叶与精确对象后端已接入统一驱动。本地 Image 对元数据使用逐字原子访问，远端只用 NIC 原子；物理持有者按会话预分配。锁计数按全 cohort 会话汇总，指定事务的诊断计数扫描持有者 slab，非热路径且在排空后精确。释放时清除 holder 身份，避免复用后的诊断残留。

远端普通值更新的记录由 24 字节扩为含 latch 的 32 字节，数据格式从 1 升为 2；两百万配置的数据容量须按新布局重新检查，不沿用旧的 357 MiB 等数字。

硬件完整 CTest：`experiments/logs/shared-check-20261104-160025-928487/ctest.stdout`，44/44 全执行、零跳过。新增缺失 Update 专项检查，确认共享 topology 权限不能直接触发插入，而要释放后以 X 重试。两机定向 31 项检查：`experiments/logs/leaf-check-20261104-155845-094073/state.json`。其中四类仅锁连接断开故障、三策略双进程两记录精确和值、四个现有子负载×三策略×本地/跨机均通过。它们是正确性/入口验证，不能用作正式性能排名。

容量候选配置 `formal_native_leaf_2m_10s.json`：层级维度只按真实叶规划，不重复扫描无意义的 bucket 宽度。`run_shared_matrices.py` 与报告、续跑校验会拒绝 bucket/leaf 混合。完整正式矩阵仍未启动；新二进制一小时稳定性与两百万最大并发容量检查还需单独完成。
