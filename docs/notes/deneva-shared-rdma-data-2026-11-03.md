# Deneva 单边 RDMA 数据路径迁移方案（2026-11-03）

## 问题与目标

已有跨主机结果只覆盖远端锁服务：每个 workload 进程各有自己的 BTreeLatch 和记录。它们不能作为共享数据库的 RDMA 范围查询结果，也不能证明跨进程幻读保护。历史原始数据保留，归类为锁服务微基准，禁止并入新的共享数据实验。

按用户要求移植 /home/dell/pgm_deneva_backup 的数据路径思路：注册内存内的根偏移、树节点、记录；child_offsets / next_node_offset 寻址；发起端逐层 RDMA READ，远端原子操作保护结构，RDMA WRITE 写回。保留项目公共锁接口和统一事务骨架，不搬入 Deneva 的线程框架、TPC-C 专用强转、退避及已知不安全内存访问。不引入新依赖。

## 架构与边界

- .66 的新增数据服务拥有唯一权威 B+ 树及 uint64 记录，服务端 CPU 只初始化、注册内存、建链；正常查询和修改不通过 RPC 执行。
- 客户端使用独立 QP/worker，临时节点和记录副本仅作一次操作的缓冲，不保留本地可写数据库。多个进程连接同一 MR。
- 数据、物理锁表、时间戳协调器为三个专用服务；现有 TCP 协调面明确保留，不称纯单边事务协议。一次实验只能配一套专用服务，禁止服务重启后沿用未配套的其他服务。
- 六版索引的主机页布局仍共同来自 include/index/btree.h；其 vector/unique_ptr/shared_mutex 不能跨地址空间直接读取。因此在同一个公共页布局头内增加统一的偏移线格式，所有 RDMA 锁协议必须共用该格式、相同索引实现和键比较。不能把本地布局与远端布局变化冒充单变量锁优化。
- src/index 只实现短期结构 latch、页及记录操作；事务锁只留在 src/lock，调度和提交留在 src/txn。
- 第一版使用远端共享/排他结构 latch：读操作共享、一个写批次排他。它是正确性基线，写结构串行点须公开，不宣称已实现 Sherman 的可扩展 latch。CAS 等待有绝对期限，超时为硬错误，无 sleep/随机退避或事务冲突伪装。
- 删除先标记记录无效；重插相同 key 复用记录，树叶仍有序。页不在线回收；容量用配置预分配，写前保守容量检查，不允许部分写完再返回普通容量中止。

## 公共接口增量（单独接口提交）

IRangeLockManager 原四个方法完全不变。BTreeIndex 增加有默认实现的后端能力钩子：外部初始化标记、线程缓冲准备/结束、健康状态、输出到调用方已预留向量的扫描、批量应用修改。原六版本无须改签名，默认行为保持原路径。远端覆盖这些方法；事务驱动不访问页内结构。

读返回的 void* 仅指本 worker 的值缓冲，绝不发送进程指针。写批次内的输入指针仅在本地取 uint64 值，线上存实际值。远端扫描及树操作的内存缓冲在 Begin 前预分配。

## 事务与故障

1. 数据服务按共同 workload 配置生成初始数据；客户端校验初始集合指纹、order 和元数据，只连接、不重新灌数。
2. Begin -> 统一锁计划 -> 读取同一远端索引与记录 -> PrepareCommit -> 应用整个写批次 -> 释放物理锁 -> End。
3. wound 在 PrepareCommit 前生效；提交获准后不能被 wound。未获准的事务不写共享数据。
4. 数据错误或写入结果不确定时停止整轮，保留/封闭不确定状态；不得释放物理锁后继续提供正常事务。协调器因 active session 断开进入 fail-stop。无崩溃恢复、持久化或重新上线承诺。
5. 服务启动和客户端连接阶段进行配置与容量校验；测试多进程可见性、幻读阻塞、提交与 wound/abort 顺序、尾部区间、树分裂、删除重插、空区间和 uint64 边界。

## 验收

先纯内存线格式/算法与故障注入测试，再全 CTest、.66 回环、多独立客户端 .67->.66 正确性验证及连续一小时压力；采集远端索引/记录操作和字节数，验证实际数据跨网。只跑正确性与定向验证，不启动正式性能矩阵。结果与限制写报告，中文里程碑提交并正常 push。
