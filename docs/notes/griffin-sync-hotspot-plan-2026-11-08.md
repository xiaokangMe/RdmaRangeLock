# Griffin 同步与热点验收完善方案

基线 d6d3f3c；用户授权完成指标、同步优化、热点活性验证，不启动正式矩阵。

1. 本地混合索引增加只读诊断快照：当前/峰值积压批次与待同步key、提交批次/成员操作数、同步轮次/批次数/实际树操作数、容量拒绝、同步工作耗时与排队至复制完成延迟。统一runner在测量开始前排空warmup同步并重置指标，在测量结束、validate排空之前采样，避免将验证算入测量。CSV末尾追加字段，其他后端为0。
2. 在修改hash前模拟最终key成员状态，纯值更新或成员净变化为0的批次不消耗队列容量；跨多key批次如需容量且队列满，整批无副作用地拒绝。队列仍有严格容量上界，正在复制的批次也计入。
3. sync manager一次取至可配置上限的FIFO批次，同key只应用最后成员状态；所有原始pending计数在整个同步组成功后统一清除。树修改在结构fence外执行，pending保护始终保留；扫描持shared fence检查pending并扫描，和同步相交的扫描中止，不相交扫描由共用BTreeLatch保护结构。同步组不与下一同步组并行。
4. 错误先发布failed，再唤醒等待者；所有故障封闭与原有严格2PL保持。配置增加griffin_sync_batch_limit，默认64、可设1作消融；不是Griffin-PPL。
5. 新增可复现32线程全热点短探针，覆盖三等待策略、两协议和混合索引，输出完成比例、重试耗尽、等待、含重试尾延迟；no-wait不得假设无饥饿。另保留确定性年龄/升级交错验证，失败不得删测或放宽断言。
6. 针对容量、副作用、批内/跨批合并、复制中的pending、指标与warmup边界写确定性回归；CTest、ASan/UBSan、TSan和有界结构压力验收。代码和配置一个优化里程碑中文提交、普通push。旧实现一小时压力记录保留且不冒充优化后数据。

## 全热点探针判定口径补充

新探针最初对wait-die/wound-wait加入“任意1秒调度窗口必有提交”的断言，实测wait-die在读锁升级重入中出现零提交。该断言并非论文保证：年龄顺序只排除死锁环，不能排除新读者持续进入导致等待升级饥饿，OS调度也无固定时间保证。不能用延长时间或随机退避掩盖。正确性断言（两键原子结果、无硬错误/锁泄漏、所有计数守恒）保持；受控交错仍要求老事务在年轻持有者实际清理后获得写锁并提交。开放窗口明确输出progress_observed=false、零提交worker数及重试耗尽，不把“没有数据错误”等同“活性达标”。本轮不擅自改变共享锁授权、增加写者优先队列或声称修复所有饥饿。
