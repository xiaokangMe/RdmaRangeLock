## 2. 项目是什么

一篇关于"范围查询在并发控制中的语义"的综述，配套**六个可跑的最小实现**，用同一棵 B+ 树、
同一套 workload 逐层叠加锁机制：

| 版本 | 机制 | 关键文件 |
|---|---|---|
| v1 | 单线程 B+ 树（基线） | `src/index/v1_btree_single.cpp` |
| v2 | 并发 B+ 树 + latch coupling | `src/index/v2_btree_latch.cpp` |
| v3 | 记录级 Strict 2PL | `src/lock/lock_manager.cpp` + `src/txn/workload.cpp` 的 `run_record_2pl` |
| v4 | Gap Lock | 同上 `run_gap_lock` |
| v5 | Next-Key Lock | 同上 `run_next_key_lock` |
| v6 | Next-Key + 层级锁（IS/IX/S/X） | 同上 `run_hierarchical_lock` |

另有 RDMA 远端锁表（`src/lock/remote_lock_manager.cpp`），与本地锁表实现同一个
`IRangeLockManager` 接口，因此 v5/v6 协议代码只有一份。

核心主张写在 `README.md` 第一节：**综述不能只靠讲故事，每类锁机制都要有能跑的实现和可对比的数据。**
所以"没有对应实现的论断不写进文章"是这个项目的硬要求。

## 3. 硬约束（先读 `CONSTRAINTS.md`，这里只摘最容易踩的）

1. `src/index/` 只允许有 latch，禁止事务级锁；`src/lock/` 只允许有锁，禁止碰页内结构。
2. v1~v6 必须共用同一套页布局与 key 比较逻辑（`include/index/btree.h`），否则性能不可比。
3. 禁止用 `sleep`、重试、随机退避去绕开并发 bug；看到死锁修锁顺序。
4. 禁止为通过测试而放宽断言。
5. 任何性能数字必须同时有：`experiments/configs/` 的配置、`experiments/results/` 的原始数据、
   生成它的 commit hash。
6. 对比实验只允许单变量；每版至少跑三次，报波动范围，不许挑最好的一次。
7. 图必须由 `scripts/` 下的脚本生成，`figures/` 只存产物，禁止手工截图。
8. 原始数据、编译产物、运行日志不入库。
9. 一个版本一次提交，提交信息第一行写明实现了哪个不变式/新增什么能力；不 force push。

## 5. 实测坑（省你重新踩）

| 坑 | 现象 | 应对 |
|---|---|---|
| B 树里存的是裸指针指向外部 value 数组 | 数组中途 `resize` 会让已插入指针悬空，`validate()` 通过但数据是脏的 | 值存储必须一次性预分配到位（`benchmarks/latch_path_bench.cpp` 已这么做） |
| `run_formal_matrix.sh` 的 CSV 校验曾比对表头前缀 | 第一个 case 就被判 invalid，`set -e` 直接退出整轮 | 已修；新增校验时注意 `tail -n 1` 拿到的是数据行 |
| 远程锁表分片按 `key / bucket_width % 16` 映射 | 连续范围锁天然挤在相邻分片，容量满了返回 `Abort`，看起来像"冲突" | 容量类中止要看 `abort_capacity` 计数，别看总 abort |
| `.66` 上默认没有 matplotlib | 直接跑绘图脚本 traceback | `pip3 install --user -r scripts/requirements.txt`（不在系统包里） |
| `experiments/results/*.csv` 被 gitignore | 数据不会进仓库，clone 下来只剩图和报告 | 结论必须带 sha256 + 路径，参照 `docs/reports/README.md` |
| 两份不同提交要对比 | 新基准文件在旧提交里不存在 | 用独立 worktree 构建旧版静态库，再把基准源文件链接进去，编译参数保持 `-O3 -DNDEBUG` |
| 高线程 + 大 range 的 case 极慢 | `record-2pl / range=128 / t32` 可能逼近 900 秒超时 | 缩短矩阵或用 `RRL_TIMEOUT_SECONDS` 放宽，别让超时吃掉整轮 |
