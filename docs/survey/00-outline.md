# 综述提纲：范围查询与范围锁

## 一句话定位

点查的并发控制只需保证"这一行不被同时改"，而**范围查询要保证"这一段区间里不会凭空出现新行"**——这就是幻读，也是范围锁全部复杂性的来源。本文沿着"如何用一个可计算的锁集合去覆盖一个谓词"这条主线，梳理从记录锁到层级锁的演化。

## 主线论证

范围锁的本质是把**谓词**映射成**索引结构上的可枚举对象**：

```
谓词 P（如 age BETWEEN 20 AND 30）
   ↓ 依赖索引结构
索引上的连续对象集合（若干 key + 若干间隙）
   ↓ 选择锁粒度
锁集合（记录锁 / 间隙锁 / next-key 区间 / 层级意向锁）
```

这条链上每一步都引入一种代价，综述就是逐个拆解这些代价。

## 分类维度（正文的核心表格）

| 维度 | 取值 | 代表方案 |
|---|---|---|
| 锁的载体 | 数据记录 / 索引项 / 间隙 / 谓词本身 | record、next-key、predicate lock |
| 粒度控制 | 单一粒度 / 多粒度层级 | 2PL、多粒度锁（IS/IX/S/X） |
| 与索引的耦合 | 索引无关 / 依赖 B+树顺序 | 谓词锁 vs next-key lock |
| 幻读处理 | 不处理 / 靠间隙 / 靠快照 | v3 / v4-v5 / MVCC |
| 结构并发 | 无 / latch coupling / 无锁结构 | v1 / v2 / Bw-tree |
