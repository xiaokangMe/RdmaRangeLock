# 2. 背景：B+ 树、范围扫描与谓词

## 本节要回答的问题

- [ ] B+ 树的节点布局与范围扫描的访问路径（为什么范围扫描必然经过"间隙"）
- [ ] 索引项、页、兄弟指针三者的关系，以及 latch 需要覆盖的范围
- [ ] 谓词如何映射到索引上的区间：闭/开区间、无界扫描、前缀匹配
- [ ] "间隙"的精确定义：两个相邻 key 之间、以及首尾两个边界外

## 关键概念

**间隙（gap）** 不是一个实体，而是相邻两个 key 之间的**开区间**。它不能被"锁"，只能被"标记为受到保护"。这是 next-key lock 与记录锁在实现上一个常被忽略的差别。

**范围扫描的物理路径**：root → 叶节点（通过内部节点的 key 比较）→ 沿叶节点兄弟指针右移。因此一次范围查询会触及：一条自顶向下的路径 + 若干叶节点 + 叶节点之间的边界。

**谓词到区间的映射**有三个易错点：

1. 边界包含性（`>` vs `>=`）决定是否要锁住边界 key 本身
2. 无界扫描（`WHERE k > 20` 且无上界）需要保护到"无穷"，即索引最右端之外
3. 空结果集也要保护——没有任何行被返回，不代表没有间隙需要锁
